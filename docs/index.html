C# and F# with nothing underneath

A fork of bflat compiles C# and F# straight to a small native program: no .NET runtime, no garbage collector, nothing to install where it runs.

You keep the language's syntax, type checking and generics: C#'s records and pattern matching, or F#'s unions, active patterns and units of measure (write F#). Memory comes from arenas you free all at once, and a small library gives you strings, collections, input and output on those terms. The same source runs on Linux, macOS and Windows, on WebAssembly, on DOS on a 386, on a bare PC with no operating system, started by its UEFI firmware, and on a Commodore 64.

The language stays, the runtime goes

The compiler still checks everything it checks in .NET. What's missing is what a runtime would do while your program runs.

You keep

  • C# 15Unions, extension members and the new memory safety rules.
  • Real genericsA specialized copy for each type, and static abstract members.
  • Interfaces and virtual methodsDefault interface methods, casts, is and as.
  • Records, tuples, anonymous typesValue equality, with, and the generated ToString.
  • Lambdas and queriesWhere, Select and GroupBy, from a small library instead of LINQ.
  • ThreadsParallel.For runs a loop on every core.

You do without

  • Garbage collectorArenas free their memory all at once, when you say.
  • .NET runtimeHello world is 11 KB on Windows and 40 KB on Linux, with nothing to install.
  • Catching exceptionsthrow ends the program. Return errors as unions.
  • Reflection and asyncA type can be compared, but it has no name.

One program, six machines

A new project from dotnet new zero, built for each target by setting one property, ZeroTarget. The repository builds WebAssembly and DOS too, and one test suite requires the same output on every target.

And a Commodore 64

The repository also builds for the home computer from 1982: a 1 MHz 6502 with 64 KB of memory. The same bitcode as for WebAssembly is rewritten for 16-bit addresses and compiled by llvm-mos.

Nineteen of the test programs run there, and so does this game: records, a union and pattern matching, sprites, the keyboard, and music on the SID chip, in 37 KB, with nothing allocated while it plays.

Build for the Commodore 64

Recorded in the VICE emulator. A project builds for the C64 with dotnet build -p:ZeroTarget=c64 (on a Mac, with Docker running).

A language model, in F#

Karpathy's stories260K, a Llama-style model of 260,000 parameters, tells a story on the same machine. Its weights wait in a 512 KB RAM Expansion Unit, and the C64 copies in a row at a time.

All of the program is F#, in integers only: int8 weights, struct unions, active patterns, and units of measure that keep an REU address from passing for a C64 one. Its next token matches the floating-point model's 98% of the time, at about a minute a token.

What's different, and what you get

Without a runtime, a few things work differently. Each has a page that explains why and what to do instead.

  • Memory is yours to free

    There is no garbage collector, so new is never freed. Arenas hand out memory and free it all at once, one per lifetime.

    Memory without a garbage collector

  • Text without throwaway strings

    Out.Line($"...") formats straight into the output buffer, and In.ReadLine reads into a span. Strings that must last go into an arena.

    Strings without a garbage collector

  • Collections that live in arenas

    List, Dict, and their versions for references and string keys, all handles into an arena.

    Choose a collection

  • C# 15, with the safety rules on

    Every program compiles under the updated memory safety rules: creating a pointer is safe, reading through one is marked and explained.

    The memory safety rules
